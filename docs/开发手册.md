## 一、项目概述

### 1.1 背景

面向企业各部门（运营、客服、设计、仓储等），通过结构化调研收集业务场景信息，再利用AI大模型分析识别各业务环节中可引入AI提效的具体环节，输出可执行的AI提效建议报告。

### 1.2 双重定位

| 定位 | 说明 |
|------|------|
| **独立程序** | Python程序可直接运行，填写业务数据后自动生成AI提效分析报告，交付领导 |
| **Skill包** | 同一套代码可打包为Skill格式（SKILL.md + manifest.json + 资源文件），分发给其他Agent平台复用 |

### 1.3 核心价值

- **调研标准化**：预设各部门调研模板，统一信息采集口径
- **分析智能化**：基于大模型自动识别AI提效机会点
- **输出可执行**：报告包含场景描述、建议AI技术、预期提效比、落地优先级
- **分发便捷化**：一键打包Skill，可在ZCode/其他Agent平台直接加载使用
- **使用傻瓜化**：GUI界面，选文件点提交，无需懂代码

### 3.3 AI分析引擎模块 (`core/ai_engine.py`)

**职责：** 调用大模型，对采集的业务数据进行AI提效机会点分析，支持异步并发。

**核心类：**

```python
import asyncio
from typing import Dict, List

class AIAnalysisEngine:
    def __init__(self, config: Config):
        self.llm_client = LLMClient(config)
        self.prompts = self._load_prompts()
        self.semaphore = asyncio.Semaphore(3)  # 限制并发数为3，防止触发API限流
    
    async def analyze_department(self, dept_data: Dict) -> AnalysisResult:
        """异步分析单个部门"""
        # 使用 semaphore 控制并发，防止触发 API rate limit
        async with self.semaphore:
            messages = self._build_analysis_prompt(dept_data)
            response = await self.llm_client.chat(messages)
            return self._parse_llm_response(response)
    
    async def analyze_all(self, all_data: Dict) -> FullAnalysisReport:
        """异步并发分析所有部门"""
        tasks = [self.analyze_department(d) for d in all_data.values()]
        return FullAnalysisReport(results=await asyncio.gather(*tasks))
```

**分析维度（配置化）：**

| 维度 | 说明 |
|------|------|
| **重复性** | 该环节是否高度重复、规则明确 |
| **数据密集度** | 是否涉及大量数据处理/分析 |
| **人力成本** | 该环节占用的人力/时间成本 |
| **AI成熟度** | 现有AI技术在该场景的成熟度 |
| **落地难度** | 引入AI的实施难度和成本 |
| **提效预期** | 预期可节省的人力/时间比例 |

**配置化定义（config.yaml）：**


#### 3.6.2 LLM客户端 (`infra/llm_client.py`) — 策略模式

```python
class LLMProvider(ABC):
    @abstractmethod
    def chat(self, messages: List[Dict], **kwargs) -> str: pass

class OpenAIProvider(LLMProvider): pass
class QwenProvider(LLMProvider): pass
class ZhipuProvider(LLMProvider): pass

PROVIDERS: Dict[str, Type[LLMProvider]] = {
    "openai": OpenAIProvider,
    "qwen": QwenProvider,
    "zhipu": ZhipuProvider,
}

class LLMClient:
    def __init__(self, config: Config):
        self.provider = PROVIDERS[config.llm_provider](config)
    
    def chat(self, messages: List[Dict], **kwargs) -> str
    def chat_structured(self, messages: List[Dict], schema: Dict) -> Any
```

新增模型只需加一个Provider类，无需修改核心代码。

```python
def setup_logger(name: str, level: str = "INFO") -> logging.Logger:
    logger = logging.getLogger(name)
    handler = logging.StreamHandler(sys.stdout)
    formatter = JsonFormatter(
```

```python
class GUIApp:
    """GUI主应用"""
    
    def __init__(self):
        self.root = tk.Tk()
        self.root.title("AI业务调研提效分析系统 v1.0")
        self.root.geometry("800x600")
        self.setup_ui()
    
    def setup_ui(self):
        """设置界面布局"""
        # 输入文件选择
        self.file_label = tk.Label(text="选择调研总结文件:")
        self.file_entry = tk.Entry(width=60)
        self.browse_btn = tk.Button(text="浏览...", command=self.browse_file)
        self.clear_btn = tk.Button(text="清空", command=self.clear_file)
        
        # 输出格式选择
        self.format_var = tk.StringVar(value="md")
        tk.Radiobutton(self.root, text="Markdown", variable=self.format_var, value="md").pack(anchor="w", padx=20)
        tk.Radiobutton(self.root, text="Excel", variable=self.format_var, value="xlsx").pack(anchor="w", padx=20)
        tk.Radiobutton(self.root, text="JSON", variable=self.format_var, value="json").pack(anchor="w", padx=20)
        
        # 分析深度选择
        self.depth_var = tk.StringVar(value="standard")
        tk.Radiobutton(self.root, text="快速分析", variable=self.depth_var, value="quick").pack(anchor="w", padx=20)
        tk.Radiobutton(self.root, text="标准分析", variable=self.depth_var, value="standard").pack(anchor="w", padx=20)
        tk.Radiobutton(self.root, text="深度分析", variable=self.depth_var, value="deep").pack(anchor="w", padx=20)
        
        # 提交按钮
        self.submit_btn = tk.Button(text="提交分析", command=self.submit_analysis)
        self.cancel_btn = tk.Button(text="取消", command=self.cancel)
        
        # 进度条
        self.progress = ttk.Progressbar(self.root, maximum=100)
        self.status_label = tk.Label(text="等待操作...")
        
        # 绑定事件
        self.root.bind('<Control-o>', lambda e: self.browse_file())
        self.root.bind('<Control-s>', lambda e: self.submit_analysis())
    
    def browse_file(self):
        """浏览选择文件"""
        filetypes = [
            ("Markdown文件", "*.md"),
            ("纯文本文件", "*.txt"),
            ("Word文档", "*.docx"),
            ("JSON文件", "*.json"),
            ("所有文件", "*.*"),
        ]
        filepath = tk.filedialog.askopenfilename(
            title="选择调研总结文件",
            filetypes=filetypes
        )
        if filepath:
            self.file_entry.delete(0, tk.END)
            self.file_entry.insert(0, filepath)
    
    def submit_analysis(self):
        """提交分析"""
        # 1. 验证输入
        filepath = self.file_entry.get()
        if not filepath:
            messagebox.showwarning("提示", "请先选择输入文件")
            return
        
        # 2. 禁用提交按钮，显示进度
        self.submit_btn.config(state=tk.DISABLED)
        self.progress['value'] = 0
        self.status_label.config(text="正在解析文件...")
        
        # 3. 异步执行分析（不阻塞界面）
        threading.Thread(target=self._run_analysis, args=(filepath,), daemon=True).start()
    
    def _run_analysis(self, filepath: str):
        """后台执行分析（不阻塞GUI）"""
        try:
            self.status_label.config(text="正在解析文件内容...")
            self.progress['value'] = 10
            
            # 解析文件
            if filepath.endswith('.docx'):
                content = self._parse_docx(filepath)
            elif filepath.endswith('.json'):
                content = self._parse_json(filepath)
            else:
                content = self._parse_text(filepath)
            
            self.status_label.config(text="正在AI分析...")
            self.progress['value'] = 30
            
            # AI分析（异步并发）
            try:
                analysis = asyncio.run(self.engine.analyze_all(content))
            except RuntimeError as e:
                self.status_label.config(text="程序已关闭")
                return
            except Exception as e:
                self.status_label.config(text=f"AI分析失败：{str(e)}")
                return
            
            self.status_label.config(text="正在生成报告...")
            self.progress['value'] = 80
            
            # 生成报告
            output_format = self.format_var.get()
            output_path = self._generate_report(analysis, output_format)
            
            self.status_label.config(text="完成！")
            self.progress['value'] = 100
            
            # 弹出提示
            messagebox.showinfo("成功", f"报告已生成！\n\n路径：{output_path}")
            
            # 自动打开报告（跨平台）
            self._open_file(os.path.dirname(output_path))
            
        except Exception as e:
            messagebox.showerror("错误", f"分析失败：{str(e)}")
        finally:
            self.submit_btn.config(state=tk.NORMAL)
    
    def _parse_docx(self, filepath: str) -> Dict:
        """解析Word文档"""
        from docx import Document
        doc = Document(filepath)
        # 提取段落和标题
        content = "\n".join([p.text for p in doc.paragraphs])
        return self._parse_text_content(content)
    
    def _parse_json(self, filepath: str) -> Dict:
        """解析JSON文件"""
        with open(filepath, 'r', encoding='utf-8') as f:
            return json.load(f)
    
    def _parse_text(self, filepath: str) -> Dict:
        """解析文本文件"""
        with open(filepath, 'r', encoding='utf-8') as f:
            content = f.read()
        return self._parse_text_content(content)
    
    def _parse_text_content(self, content: str) -> Dict:
        """解析文本内容，识别部门和业务场景"""
        # 简单解析：按标题分割
        departments = {}
        current_dept = "未知部门"
        for line in content.split('\n'):
            if line.startswith('# '):
                current_dept = line[2:].strip()
            elif line.strip():
                if current_dept not in departments:
                    departments[current_dept] = []
                departments[current_dept].append(line)
        return departments
    
    def _generate_report(self, analysis: FullAnalysisReport, output_format: str) -> str:
        """生成报告"""
        output_dir = Path("./output")
        output_dir.mkdir(exist_ok=True)
        output_path = output_dir / f"report.{output_format}"
        if output_format == 'md':
            self.report_gen.generate_markdown(analysis, output_path)
        elif output_format == 'xlsx':
            self.report_gen.generate_excel(analysis, output_path)
        elif output_format == 'json':
            self.report_gen.generate_json(analysis, output_path)
        return str(output_path)

    def _open_file(self, directory: str):
        """跨平台打开文件目录"""
        if sys.platform == 'win32':
            os.startfile(directory)
        elif sys.platform == 'darwin':
            import subprocess
            subprocess.run(['open', directory])
        else:
            import subprocess
            subprocess.run(['xdg-open', directory])

    def cancel(self):
        """取消"""
        self.root.quit()
    
    def run(self):
        """运行GUI"""
        self.root.mainloop()

if __name__ == "__main__":
    app = GUIApp()
    app.run()
```

## 十五、文档解析策略

**支持的输入文件类型：**

| 类型 | 扩展名 | 说明 |
|------|--------|------|
| Markdown | .md | 推荐，格式规范 |
| 纯文本 | .txt | 直接读取内容 |
| Word文档 | .docx | 需安装python-docx |
| JSON | .json | 结构化数据，最精确 |

**公共解析函数：**

```python
def parse_text_content(content: str) -> Dict:
    """解析文本内容，识别部门和业务场景（通用解析逻辑）"""
    departments = {}
    current_dept = "未知部门"
    current_scene = None
    
    for line in content.split('\n'):
        line = line.strip()
        if not line:
            continue
        
        # 识别部门标题（# 开头，非##）
        if line.startswith('# ') and not line.startswith('## '):
            current_dept = line[2:].strip()
            departments[current_dept] = []
            current_scene = None
        # 识别场景标题（## 开头）
        elif line.startswith('## '):
            current_scene = line[3:].strip()
            if current_dept not in departments:
                departments[current_dept] = []
        # 识别场景内容（列表项）
        elif line.startswith('- ') or line.startswith('• ') or line.startswith('* '):
            if current_dept in departments and current_scene:
                departments[current_dept].append({
                    "scene": current_scene,
                    "content": line[2:].strip()
                })
        # 普通段落
        elif current_dept in departments and current_scene:
            if departments[current_dept] and departments[current_dept][-1].get("scene") == current_scene:
                departments[current_dept][-1]["content"] += " " + line
    
    return departments
```

**Word文档（.docx）解析（提取后调用公共函数）：**

```python
from docx import Document

def parse_document(filepath: str) -> Dict:
    """解析Word文档，提取内容后调用公共解析函数"""
    doc = Document(filepath)
    content = "\n".join([p.text for p in doc.paragraphs])
    return parse_text_content(content)
```

**解析规则：**

1. **标题识别**：`# XXX部` → 部门，`## XXX` → 场景
2. **列表识别**：`- `或`* `开头的行 → 列表项
3. **段落识别**：非标题、非列表的连续行 → 段落内容
4. **空行**：段落分隔符

**示例文档结构：**

```
# 运营部
## 用户增长
当前流程：人工分析渠道数据，手动制定投放策略
耗时：每天约2小时
痛点：数据量大，人工统计慢

## 内容分发

耗时：每天约4小时
```

## 二十五、日志与 AI Agent 操作指引

本系统专门为"AI Agent 操作"设计了一套可观测、可调试的接口。凡是 Agent 接入本项目做测试、读日志、修 bug，都按本章约定执行。

### 25.1 结构化 JSON 日志

- 日志模块名：`ai-efficiency`（`infra/logger.py` 基于 python-json-logger）。
- 默认输出到 `./logs/app.log`（RotatingFileHandler，单文件 10MB、保留 5 份：`app.log`、`app.log.1` … `app.log.5`），同时输出到 stdout。
- 每行是一个 JSON 对象，字段：`timestamp`（ISO8601）、`level`（INFO/WARNING/ERROR）、`module`（源模块 logger 名）、`message`。

```json
{"timestamp": "2026-10-16T10:00:00", "level": "INFO", "module": "core.ai_engine", "message": "部门 运营 分析完成: 3 个机会点"}
```

**Agent 读日志约定：**

```bash
# 读最近日志（tail + jq 按级别过滤）
tail -n 100 ./logs/app.log | jq 'select(.level=="ERROR")'

# 定位某次分析失败原因
grep -n "ANALYSIS_ERROR\|LLM_ERROR" ./logs/app.log
```

- 每个 `AppError` 子类携带机器可读的 `code` 字段（如 `LLM_API_KEY_MISSING`、`REPORT_GENERATION_FAILED`、`PACK_ERROR`），日志与异常消息中会带出，Agent 可按 code 精确分类错误。

### 25.2 CLI 调试接口（Agent 主入口）

GUI 面向人；Agent 一律走 CLI，所有命令在 Windows 下用 Git Bash 或 PowerShell 直接执行：

```bash
cd <项目根目录>
uv run python main.py --cli --help          # 查看全部子命令
uv run python main.py --cli departments     # 列出 5 个部门模板（无需 API Key，冒烟测试）
uv run python main.py --cli analyze --input <调研文件.md> --output-format json
uv run python main.py --cli collect         # 交互式采集（Agent 可用 echo 管道喂答案）
uv run python main.py --cli quick-start     # 交互式引导配置
```

约定：

- **无 Key 冒烟**：`departments` 不触发 LLM，用于快速验证安装与模板完整性。
- **缺 Key 行为**：`analyze` 在 LLM 调用前即抛 `LLMError(code="LLM_API_KEY_MISSING")`，退出码非 0，stderr 有消息——Agent 看到该 code 就知道该让用户配 Key（环境变量 `LLM_API_KEY`，或 config.yaml `model.api_key`，也可用 `LLM_PROVIDER`/`LLM_BASE_URL`/`LLM_MODEL_NAME` 覆盖其余模型参数）。
- **输出可机读**：`--output-format json` 产出的报告是标准 JSON，Agent 可直接解析校验；报告文件落在 `./output/report_<时间戳>.<ext>`。
- **产物固定路径**：日志 `./logs/app.log`、报告 `./output/`、SQLite 缓存 `./cache.db`（默认），Agent 巡检按这三处找。

### 25.3 事件总线（Agent 侧扩展点）

`infra/event_bus.py` 暴露 5 个事件常量：`TEMPLATE_LOADED`、`DATA_COLLECTED`、`ANALYSIS_DONE`、`REPORT_GENERATED`、`PACK_DONE`。`REPORT_GENERATED` 的 payload 含 `filepath`、`format`、`total_opportunities`、`high_priority_opportunities`、`generated_at`。Agent 做自动化验收时可在测试脚本里 `subscribe(REPORT_GENERATED, handler)` 监听产物落地，而不是轮询文件系统。

## 二十六、AI Agent 接入与调试指南（修 bug 路径）

给"接手本项目的 AI Agent"的标准作业流程（SOP），配合上文日志约定使用：

1. **安装**：`cd 项目根 && uv sync`（含 dev 依赖 pytest/pytest-asyncio）。
2. **冒烟**：`uv run python main.py --cli departments` 应列出 5 个部门；失败说明环境或模板损坏。
3. **全量测试**：`uv run pytest -q`（tests/ 下 unit/integration/E2E 全部离线可跑，无需 API Key）。
4. **定位问题**：
   - 先读 `./logs/app.log` 最近 100 行（25.1 的 jq 命令）；
   - 按异常 `code` 定位层：`*_ERROR` code 与 `infra/exceptions.py` 的子类一一对应（Config→config.yaml；Template→templates/；Collection→输入文件格式；Analysis/LLM→模型调用与 Key；Report→输出格式/模板；Pack→Skill 打包）；
   - GUI 崩溃看线程堆栈（日志带 `exc_info`）。
5. **修 bug**：只改 `domain/ infra/ core/ entry/ output/` 源码；测试写在 `tests/` 对应层级，不允许改产品代码迁就测试。
6. **验证**：重跑 2 + 3，全绿后提交。

## 二十九、注意事项

1. **API Key安全**：优先通过环境变量注入API Key，config.yaml中可留空
2. **config.yaml权限**：文件权限设为600（仅owner可读写）
3. **模型调用限制**：注意各模型的token限制和并发限制，做好重试机制
4. **模板维护**：部门模板应独立维护，方便非技术人员编辑
5. **Skill兼容性**：打包的Skill需遵循目标平台（ZCode等）的Skill规范
6. **数据隐私**：业务数据直接上传给LLM，注意数据安全
7. **Windows部署**：使用PyInstaller打包为.exe，双击安装，非技术人员可用
8. **依赖锁定**：使用uv.lock锁定依赖版本，确保跨环境一致
9. **LLM并发控制**：AI分析引擎默认使用`asyncio.Semaphore(3)`限制并发数为3，避免触发API限流；如需调整，修改`AIAnalysisEngine.__init__`中的Semaphore参数
10. **GUI跨平台支持**：GUI使用Tkinter内置库，支持Windows/macOS/Linux跨平台运行；文件打开方法`_open_file`通过`sys.platform`判断当前平台调用对应命令（`os.startfile`/`open`/`xdg-open`）
