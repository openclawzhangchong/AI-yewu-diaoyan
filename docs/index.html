三步出报告

使用流程从调研到报告，人类最笨的操作路径

1

把调研内容写成文件

每个部门一份文件，自然语言写清楚「当前流程、耗时、痛点」即可，不需要任何特殊格式。

# 运营部.md —— 示例 ## 用户增长 当前流程：人工分析渠道数据，手动制定投放策略 耗时：每天约 2 小时 痛点：数据量大，人工统计慢

支持 .md / .txt / .docx / .json，混合来源都行

2

配一次 Key（只配一次）

环境变量或本地 config.local.yaml 任选其一，之后程序直接跑。

# 方式 A：环境变量（Windows cmd） set LLM_API_KEY=sk-xxxx set LLM_PROVIDER=openai set LLM_MODEL_NAME=gpt-4o-mini # 方式 B：config.local.yaml（与程序同目录，已 gitignore） model: provider: "openai" api_key: "sk-xxxx"

配优先级：命令行参数 > 环境变量 > config.local.yaml > config.yaml

3

跑一下，收报告

GUI 版：双击 exe → 选文件 → 提交 → 等报告。CLI 版：一条命令。

python main.py # 启动 GUI（傻瓜模式） python main.py --cli departments # 冒烟：列 5 个部门模板，不要 Key python main.py --cli analyze --input 客服部.md --output-format json python main.py --cli pack-skill # 打包成 Skill 分发 # 报告落在 ./output/report_时间戳.格式

缺 Key 不崩：GUI 提交时弹窗提示，CLI 友好报错并给出机器可读 code

AI Agent 接入设计

为 Agent 而造不是给人看的日志堆，是可程序化操作的一切

可机读

JSON 结构化日志

./logs/app.log 每行一个 JSON 事件（timestamp / level / message / event），jq 一行命令过滤任意事件，不用 grep 人眼找。

可判定

固定错误 code + 退出码

LLM_API_KEY_MISSING、TEMPLATE_NOT_FOUND 等固定 code，Agent 看到 code 就知道该让用户干什么，不用猜报错文本。CLI 失败 exit≠0 且无裸 traceback。

可监听

事件总线 5 事件

TEMPLATE_LOADED / DATA_COLLECTED / ANALYSIS_DONE / REPORT_GENERATED / PACK_DONE，测试与自动化可订阅事件验收，不用轮询文件系统。

可验收

固定产物路径 + SOP

日志 ./logs/app.log、报告 ./output/、缓存 ./cache.db 三处固定。开发手册 §二十六 给 Agent 完整 SOP：冒烟 → 全量测试 → 按 code 定位层 → 只改源码 → 复验。

# Agent 巡检三板斧（详见开发手册 §二十五） jq 'select(.level=="ERROR")' logs/app.log # 最近所有错误 jq 'select(.event=="REPORT_GENERATED")' logs/app.log # 最近一次报告产物路径 python main.py --cli analyze --input 调研.md --output-format json # 失败时看 code
